# Provenance — test/firmware-rehosting/cnc-grbl/

This directory rehosts a real **GRBL CNC motion-controller** firmware
targeting an **STM32F407VG (Cortex-M4)**. It exercises halucinator
against unmodified third-party firmware: the firmware boots, neutralises
its clock/SysTick/USART busy-waits via intercepts, and emits its real
serial console output (the `$N=` settings dump and the `Grbl 0.8c`
startup banner).

**The firmware binary is not shipped in this repository.** `CNC.elf`,
`CNC.bin`, and `cnc_addrs.yaml` are produced at test time by
`extract.sh` from the P2IM real-firmware dataset, and the symbol map is
regenerated by halucinator's own `hal_make_addr`.

## Source

`extract.sh` uses the prebuilt, unstripped ARM ELF shipped in the
[`RiS3-Lab/p2im-real_firmware@d4c7456`](https://github.com/RiS3-Lab/p2im-real_firmware/tree/d4c7456574ce2c2ed038e6f14fea8e3142b3c1f7)
dataset (pinned, 2020-12-11) — `binary/CNC`. That binary is GRBL built
for an STM32F407 board (the dataset's `CNC/` tree: `grbl/` engine +
`board/` STM32F4 drivers + `stm32f407vg_flash.ld`). No cross-compiler is
needed because the dataset ships the ELF with full symbols.

| Setting | Value |
|---------|-------|
| MCU     | STM32F407VG (Cortex-M4; emulated as cortex-m3 — GRBL is integer-only) |
| Flash   | 0x08000000 (carved flat from the ELF PT_LOAD segments) |
| RAM     | 0x20000000 (128 KB) + 0x10000000 CCM (64 KB) |
| Console | USART2 @ 0x40004400, captured via the `usart_putc` intercept |

## Licensing

- **GRBL** is GPLv3 (Copyright Sungeun K. Jeon and contributors). This
  directory ships only *configuration* (YAML), a small intercept handler,
  and scripts — no GRBL source or binary is committed. The binary is
  fetched from the upstream dataset at test time.
- The **P2IM real-firmware dataset** (`RiS3-Lab/p2im-real_firmware`)
  collects these firmware for rehosting/fuzzing research. Its prebuilt
  binaries are **AFL-instrumented**: each carries an `aflCall()` stub
  that issues `svc #0x3f` as a fuzzer hypercall. We intercept `aflCall`
  (return 0) so the SVC never traps under plain emulation.

## What the rehost demonstrates

Booting real motion-control firmware with **no hardware model** beyond a
catch-all peripheral region plus a handful of intercepts: the clock/PLL
and SysTick spin-waits are short-circuited, the USART TXE busy-wait is
replaced by an output-capturing intercept, and the AFL fuzz hypercall is
neutralised. The firmware then runs its real startup path
(`settings_init` → `report_init_message`) and prints the GRBL console.
